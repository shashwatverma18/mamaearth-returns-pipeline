# Mamaearth Returns Pipeline

This repository is a three-layer data and intelligence stack built for Mamaearth to measure order return rates, margin erosion, and customer growth dynamics in a deterministic, auditable flow.

## Architecture and Data Flow Lineage

The repository follows a strict three-layer lineage:

1. SQL Relational & Reporting Layer
   - The SQLite relational layer is defined in `sql/schema.sql`.
   - Data is loaded into SQLite via `sql/seed_data.sql` from the raw CSVs in the `data/` folder.
   - SQL-based KPIs and audit queries live in `sql/reports.sql` and are treated as the canonical source of raw operational findings.

2. Python Reconciliation & EDA Layer
   - `analysis/clean_and_eda.py` reads the raw CSVs directly, normalizes payment methods, deduplicates order submissions, imputes missing values, reconciles revenue with products/customers, performs outlier checks, and prints all intermediate results.
   - This layer computes the clean net revenue, return-rate hypothesis tests, cross-segmentation, month-over-month trends, and numerical deltas used downstream.

3. GenAI Insight Narrator Layer
   - `narrator/findings.json` is generated by Python from the verified metrics computed in the prior layers.
   - `narrator/generate_narrative.py` loads those values, creates an SCR narrative for regional operations and finance leadership, and falls back to a template narrative if no API key is available.

## Part 3: Visualizations and Executive Briefing

- `analysis/visualize.py` generates 300-DPI charts in `visualizations/`. The payment chart compares return rates across COD, UPI, and CARD using unique transactions. The monthly trend shows discounted net revenue after returned orders are excluded.
- `analysis/clean_and_eda.py` writes `narrator/findings.json` with the raw-to-clean revenue reconciliation, returned revenue, city return rates, payment-method return drivers, and monthly net revenue.
- `narrator/generate_narrative.py` reads that verified JSON and writes `narrator/sample_output.txt`. With `GEMINI_API_KEY` configured it requests a leadership briefing; otherwise it generates a deterministic briefing locally.
- The cost-savings figure is a planning scenario, not an observed result: it assumes 10% fewer returns and ₹150 in handling cost per avoided return. Replace these assumptions with Finance-approved unit costs before using the estimate as a target.

This lineage is intentionally deterministic:

- SQL raw KPIs are computed first and treated as source-of-truth baselines.
- Python cleaning and reconciliation derive a clean, deduplicated revenue signal grounded in the raw ledger.
- The JSON artifact exports only the metrics the Python layer already validated.
- The LLM output reads those verified values and cannot invent numbers beyond the JSON payload.

## Sequential Execution Order

Run commands in the following order:

1. SQL import and reporting
   - sqlite3 mamaearth.db < sql/schema.sql
   - sqlite3 mamaearth.db < sql/seed_data.sql
   - sqlite3 mamaearth.db < sql/reports.sql

2. Python cleaning and EDA
   - python analysis/clean_and_eda.py

3. Visualization generation
   - python analysis/visualize.py

4. Narrative generation
   - export GEMINI_API_KEY="your_key_here"
   - python narrator/generate_narrative.py

## Notes on Data Integrity

The golden rule is enforced across layers:

- No downstream layer may invent a metric.
- Every KPI in `findings.json` must have already been computed in SQL or Python.
- The narrative reads from the JSON artifact and verifies key figures before presenting them.

## Operational Purpose

This repo is designed to help leaders answer three questions with evidence:

- What share of orders are being returned by geography and payment type?
- How much margin is eroding because of duplicate submissions, returns, and outlier bulk purchases?
- Which growth levers and customer segments require intervention?
