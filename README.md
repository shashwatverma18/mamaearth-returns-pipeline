# Mamaearth Returns Pipeline

This repository is a three-layer data and intelligence stack built for Mamaearth to measure order return rates, margin erosion, and customer growth dynamics in a deterministic, auditable flow.

## Architecture and Data Flow Lineage

The CSV files in `data/` are the canonical source dataset. The SQL loader and Python analysis both consume these files; regenerate analysis outputs after changing them.

The repository follows a strict three-layer lineage:

1. SQL Relational & Reporting Layer
   - The SQLite relational layer is defined in `sql/schema.sql`.
   - Data is loaded into SQLite via `sql/seed_data.sql` from the raw CSVs in the `data/` folder.
   - SQL-based KPIs and audit queries live in `sql/reports.sql` and are treated as the canonical source of raw operational findings.

2. Python Reconciliation & EDA Layer
   - `analysis/clean_and_eda.py` reads the raw CSVs directly, reports the raw shape and payment variants, deduplicates orders, imputes missing values, reconciles revenue, flags quantity outliers, and prints the required EDA results.
   - It computes payment and city-tier return rates, correlation strengths, and monthly order value both with and without quantity outliers; the flagged rows remain in the cleaned dataset.

3. GenAI Insight Narrator Layer
   - `narrator/findings.json` is generated by Python from the verified metrics computed in the prior layers.
   - `narrator/generate_narrative.py` loads those values, creates an SCR narrative for regional operations and finance leadership, and falls back to a template narrative if no API key is available.

## Part 3: Visualizations and Executive Briefing

- `analysis/visualize.py` generates 300-DPI charts in `visualizations/`. The payment chart ranks deduplicated return rates; the monthly trend shows order value after quantity outliers are excluded and names the peak month.
- `analysis/clean_and_eda.py` writes `narrator/findings.json` from the raw-to-clean revenue reconciliation, payment return rates, highest-risk payment/city-tier segment, and outlier-corrected monthly series. It includes a derived summary for the narrator; do not edit its figures by hand.
- `narrator/generate_narrative.py` reads that verified JSON and writes `narrator/sample_output.txt` using the Situation–Complication–Resolution (SCR) structure. It checks the saved narrative for all required figures.
- The cost-savings figure is a planning scenario, not an observed result: it assumes 10% fewer returns and ₹150 in handling cost per avoided return. Replace these assumptions with Finance-approved unit costs before using the estimate as a target.

## Reproduce the Pipeline

Run these commands from the repository root, in this order:

0. Ensure Python, SQLite, and the pinned Python dependencies are available:

   ```sh
   python -m pip install -r requirements.txt
   ```

1. Create and load the SQLite relational data, then run the reports:

   ```sh
   sqlite3 mamaearth.db < sql/schema.sql
   sqlite3 mamaearth.db < sql/seed_data.sql
   sqlite3 mamaearth.db < sql/reports.sql
   ```

2. Run the independent pandas pipeline and visualization generator:

   ```sh
   python analysis/clean_and_eda.py
   python analysis/visualize.py
   ```

   Part 2 Task 5 of `analysis/clean_and_eda.py` writes `narrator/findings.json` directly from the merged, cleaned pandas results. It exports the verified revenue reconciliation, payment return rates, highest-risk payment/city-tier segment, and outlier-corrected peak month for the narrator; do not hand-edit this generated file.

3. Generate and validate the SCR narrative:

   Google AI Studio provides a Gemini API key with a free usage tier. Use a free-tier key, not a paid-only key. Keep the key private and do not commit it. To request the Gemini narrative, set the key in your shell environment and run:

   ```sh
   export GEMINI_API_KEY="your_free_tier_key"
   python narrator/generate_narrative.py
   ```

   API access is optional. For the fully offline, keyless path, unset the variable and run the same script:

   ```sh
   unset GEMINI_API_KEY
   python narrator/generate_narrative.py
   ```

   Without a key, or if the Gemini request fails, the script generates a deterministic offline SCR narrative from `findings.json`. Both paths save `narrator/sample_output.txt` and run the numeric accuracy checklist. No API spend or network access is required to grade the offline path.

This lineage is intentionally deterministic:

- SQL raw KPIs are computed first and treated as source-of-truth baselines.
- Python cleaning and reconciliation derive a clean, deduplicated revenue signal grounded in the raw ledger.
- The JSON artifact exports only the metrics the Python layer already validated.
- The LLM output reads those verified values and cannot invent numbers beyond the JSON payload.

## Requirements

The project dependencies are pinned in `requirements.txt`.

## Notes on Data Integrity

The golden rule is enforced across layers:

- No downstream layer may invent a metric.
- Every KPI in `findings.json` must have already been computed in SQL or Python.
- The narrative reads from the JSON artifact and verifies key figures before presenting them.

## Operational Purpose

This repo is designed to help leaders answer three questions with evidence:

- What share of orders are being returned by geography and payment type?
- How much margin is eroding because of duplicate submissions, returns, and outlier bulk purchases?
- Which growth levers and customer segments require intervention?
